# 入库与对齐（G1 细节）

校对开始前必须把目录变成「可逐段处理」的状态。跳过这一步，后续 diff 全是错位。

## 一、只认新布局

```
<博主目录>/
├─ 清单/works.csv
└─ 转写/<序号>_<作品ID>/text.md
```

旧布局（`文案提取/<类别>-日期/视频/`）不再支持。历史批次要校对，先用采集 skill 重新生成。

## 二、定位

```bash
python scripts/ingest.py                     # 自动找 ./抖音博主文案提取/*/
python scripts/ingest.py --project <目录>
```

命中多个会列出让你选，零个停下。**不写死路径**——历史上跨账号复用时带错数据文件，导致对账错显示。

## 三、建待校清单

| 核对 | 不一致处理 |
|---|---|
| 清单序号 vs 目录名前缀 | 以目录名为准，记 `order_mismatch` |
| 清单每条是否有目录 | 记 `missing_dir` |
| 目录是否有 `text.md` | 记 `no_text` |
| `meta.json` 的 status | `no_speech` 跳过 |

## 四、解析

段落行 `[mm:ss–mm:ss] 正文`，横线可能是 `-` / `–` / `—`，分钟位可能一位。解析后统一为 U+2013 并补零。

解析不出任何段落 → `unparsable`，不校。**宁可跳过，不可错位。**

## 五、规范化边界

只修三类，另存 `校对/normalized/`：

1. 时间戳横线统一、补零
2. 行尾空白、多余空行
3. 缺失的 `_音频总长_` 尾行按末段补

**不做**：不统一全角/半角标点、不删减文字、不合并段落、不修错字。

不统一标点的理由：ASR 标点本是模型给的，统一它既算改写，又在 diff 里制造大量无关噪音，掩盖真正的字词改动。

## 六、术语表

统计 2–5 字中文片段（≥6 次）+ 拉丁缩写（≥3 次）+ 手工补充。

- ≥10 次 → `已确认`
- 其余 → `待定`，上限 20 条

校对时只喂「该段中出现的词」，不发全表。

## 七、异常矩阵

| 现象 | 标记 | 是否校对 |
|---|---|---|
| 无 `text.md` | `no_text` | 否 |
| `status = no_speech` | `no_speech` | 否 |
| 无时间戳段落 | `unparsable` | 否 |
| 单段 > 1,500 字 | `long_para` | 是（该段跳过，其余照常） |

## 八、预算

```
校对 token ≈ 总字数 × 1.6 × 2
审核 token ≈ 校对 × 0.6
重排 token ≈ 校对 × 0.5
```

实测基准：199 篇 / 2,979 段 / 324,180 字，校对约 104 万 token。
